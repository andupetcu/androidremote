# T18: web-ui flaky tests, telemetry-based protected packages, unsupported commands

## 1. Flaky dialog tests
Root cause: the real `Modal` is a Fluent UI Dialog. Fluent's focus manager (tabster) is a per-window
singleton; after a dialog mounts or unmounts it moves/restores focus and toggles `aria-hidden` on the
dialog from timers and animation frames. Under CPU load those callbacks land in the middle of a test
(or in the next one). Observed with a DIAG dump on the failing assertion: `document.activeElement` was
`<body>`, the dialog had `aria-hidden="true"`, and the typed id was `""` or `"de"` (keystrokes lost);
other runs failed with "no accessible roles" inside a dialog that `findByRole('dialog')` had just returned.
This is why the failing test varied (followups WIPE, kioskApps, commandsAuth: every test that opens a dialog).
No app singleton (adminSocket, poller, apiFetch cache) was involved; the dialog state is the only leak.

RED (before): `npx vitest run` x10 on a quiet machine: 1 failure (followups "keeps the confirm button
disabled until the exact id is typed", 344 ms). With 8 busy-loop processes as background load: failed in
the first run, and again in most runs (`Received element is not enabled`, `Unable to find an accessible
element with the role "button"`). A "wait until focus is inside the dialog" helper did NOT fix it
(focus leaves again afterwards), so waiting is not a fix.

Fix: `src/tests/modalDouble.tsx` + a `vi.mock('../components/ui/Modal')` in `src/tests/setupTests.ts`.
The double keeps the contract the app uses (role=dialog, title, Close button, children, actions, onClose)
without the async focus machinery. No timeouts raised, no retries added. The Fluent dialog itself is
third-party code and is not under test here.

## 2. Protected packages from telemetry (tests in `src/tests/t18.test.tsx`)
`lib/deviceState.ts: effectiveProtectedPackages(telemetry, commands)`; `DeviceApps` now uses `useTelemetry`.
Telemetry `protectedPackages` wins (an empty list counts); the last SET_PROTECTED_PACKAGES command is used
only when telemetry lacks the field. One deliberate refinement: a live (not failed/expired) command created
after the last telemetry report wins until the device reports again, otherwise a fresh Protect click
would look ignored until the next telemetry upload.
RED: `Failed to resolve import "../lib/agentSupport"` (module missing; effectiveProtectedPackages missing).
GREEN: 8 tests in t18.test.tsx pass.

## 3. Commands the Android agent does not implement
Android dispatch (`CommandPollingService.kt`, the only `when`; `SessionController` has no command
strings): INSTALL_APK, UNINSTALL_APP, LOCK, REBOOT, WIPE, SET_KIOSK, DISABLE_APP, ENABLE_APP, LAUNCH_APP,
GRANT_PERMISSION, SET_PROTECTED_PACKAGES, START_REMOTE, TAKE_SCREENSHOT, GET_LOCATION, REFRESH_TELEMETRY,
SYNC_APPS, SYNC_POLICY, SET_VOLUME. Server enum values with no handler (answered "Unknown command type"):
UPDATE_APP, CLEAR_APP_DATA, CLEAR_APP_CACHE, SET_DEFAULT_APP, STOP_APP, UNLOCK, SET_BRIGHTNESS, SCREEN_ON,
SCREEN_OFF, LOST_MODE, EXIT_LOST_MODE, SET_PASSWORD, CLEAR_PASSWORD, ENCRYPT_DEVICE, CHECK_COMPLIANCE,
LIST_FILES, DOWNLOAD_FILE, UPLOAD_FILE, DELETE_FILE, RUN_SHELL, SEND_MESSAGE, PLAY_SOUND.
The only one the UI actually offered was Play Sound (Commands tab). `lib/agentSupport.ts`
(`isCommandSupported(osType, type)`) holds the list; `DeviceCommands` takes `osType` (passed by
DeviceDetail) and renders Play Sound disabled with the visible, aria-described hint "Not supported by the
Android agent" for Android devices; non-Android agents keep it. `Button` now forwards `title`,
`aria-describedby`, `aria-label`. The unused helpers (unlock, setBrightness, sendMessage) are not wired to
any control. The existing commandsAuth test that used Play Sound for the server-error case now uses Get Location.
