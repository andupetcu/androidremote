## What changed
- `lib/wsTicket.ts`: `fetchWsTicket(purpose, deviceId?)`, `buildWsUrl`.
- `lib/adminSocket.ts`: ref-counted module singleton for `/admin`, shared message-type constant list (`ADMIN_MESSAGE_TYPES`, server emits `device-event`), fresh ticket per (re)connect, no reconnect after last release or logout.
- `hooks/useAdminWebSocket.ts`: thin wrappers over the singleton; `useRealtimeEvents` and `useRealtimeDeviceStatus` listen to `device-event` and switch on `event.eventType`.
- `hooks/useRelayWebSocket.ts`: relay ticket in URL; `token` option kept only as optional "signed in" gate (RelayRemoteScreen etc. still pass it, untouched).
- `hooks/useWebRTC.ts`: only the /ws URL construction (ticket fetched, effect body otherwise unchanged and wrapped).
- `DeviceRemote.tsx`: removed unused duplicate `getRelayUrl` (with the JWT URL).
- `EnrollmentModal`, `FileBrowser` upload: `apiFetch`.
- `ConfirmDialog` (new UI component) used by DeviceCommands (lock, reboot, wipe) and AppsPage (deploy, delete); page-level error banners in DeviceCommands, AppsPage, EventsPage; `expired` status added to the type and UI; `errorMessage()` surfaces server error text; `CommandHelpers.wipe(sendCommand, deviceId)` sends `{confirm: deviceId}`.
- `InstallApkModal`: reboot default off; polls `GET /api/devices/:id/commands` and queues REBOOT per device only after INSTALL_APK is `completed`; checks `res.ok`; shows failure text; offline devices marked as queued.
- `useAuth.logout`: closes the admin socket, clears localStorage and sessionStorage, calls `POST /api/auth/logout` (best effort), Header still navigates to /login.

## Not done / needs from others
- Server: `POST /api/ws-ticket` (other agent) and `POST /api/auth/logout` do not exist yet; the UI tolerates a failing logout call. Server-side token revocation and httpOnly cookie (rest of WU-18) are server work.
- `RelayRemoteScreen.tsx`, `RelayTerminal.tsx`, `RelayFileBrowser.tsx`: still pass `token` into the hook (harmless now). RemoteScreen/useWebRTC internals (hardcoded TURN creds, console logging of pointer events and ICE candidates, 30 s command timer leak) are left for T7.
- DeviceCard/DevicesPage unenroll, group and policy deletes still use `window.confirm` (outside the finding list). There is no uninstall button in the UI today; `CommandHelpers.uninstallApp` exists but has no UI to gate.
- `useDeviceCommands` refreshes by 5 s polling while commands are in flight; it does not subscribe to live command events (avoids a second consumer of the admin socket).
- PairingFlow still uses raw `fetch` (public pairing endpoints).
