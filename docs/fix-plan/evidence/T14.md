## E. Not fixed / needs a real device or server
- The server enum lists commands the device has no handler for (`UPDATE_APP`, `CLEAR_APP_DATA`, `CLEAR_APP_CACHE`, `SET_DEFAULT_APP`, `STOP_APP`, `UNLOCK`, `SET_BRIGHTNESS`, `SCREEN_ON/OFF`, `LOST_MODE`, `EXIT_LOST_MODE`, `SET_PASSWORD`, `CLEAR_PASSWORD`, `ENCRYPT_DEVICE`, `CHECK_COMPLIANCE`, `LIST_FILES`, `DOWNLOAD_FILE`, `UPLOAD_FILE`, `DELETE_FILE`, `RUN_SHELL`, `SEND_MESSAGE`, `PLAY_SOUND`). They reach the device and fail with "Unknown command type". The web UI exposes some of them (`CommandHelpers`: unlock, brightness, message, sound). Decision needed: remove from UI/enum or implement.
- `UNLOCK`/`SEND_MESSAGE`/`PLAY_SOUND` etc. are therefore visible failures, not silent ones.
- No Android code calls the file-transfer, events or policy endpoints, so C1 on those routes is only covered by the server auth-gate matrix.
- Policy `kioskMode`/`kioskPackage` in SYNC_POLICY is a legacy flag on the device; kiosk is controlled by SET_KIOSK only (C10). The policy's kiosk package is not turned into a SET_KIOSK command anywhere.
- Protected-package list in the Apps tab is still derived from the latest SET_PROTECTED_PACKAGES command; the device now reports `protectedPackages` in telemetry (available in `useTelemetry`), not yet used there.
- Real-device only: DeviceOwner provisioning from the QR (checksum and public download), WipeGuard end to end, signal dBm values, foreground detection behind `kioskActive`, `isApplicationHidden` for `enabled`, capture, keyframe latency, TURN relay, rotation SCREEN_INFO.
