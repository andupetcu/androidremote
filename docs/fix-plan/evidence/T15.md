# T15: flaky parallel server suite

Finding IDs: none (test-infrastructure task). Component: server tests plus two small src changes.

## Reproduction (before)
Parallel `npx jest` (10 workers) failed in roughly 1 of 3 runs once the machine was busy (a dozen CPU-burning
processes, or the shared box's own load average of 15-25). A different test failed each time:
"Expected 201, got 400" (enrollment), timeouts (battery events, TRUST_PROXY login limiter), "socket hang up",
and 401s inside the t1-auth suite. Serial (`-i`) was always green.

## Root causes
1. **bcrypt cost 12 in tests.** Pure-JS bcryptjs at cost 12 takes 0.3-1.4 s per hash; tests that change the password
   or init the admin hash (SS-07/08/09) went past 5 s on a loaded box and starved the other workers.
   Fix: `bcryptRounds()` in `src/middleware/auth.ts` reads `BCRYPT_ROUNDS` (4-15), default 12 (prod unchanged);
   `test/env.ts` sets 4.
2. **`adminSessionsValidAfter` leaked between tests.** `cleanupTestDatabase()` left the `settings` table alone, so the
   timestamp written by one password-change test invalidated every admin token minted in the same second afterwards
   (`adminAuthHeader()` tokens carried only a second-resolution `iat`). Slow bcrypt widened the window, giving random
   401s that surfaced as 400/undefined-token failures downstream. Fix: `cleanupTestDatabase()` deletes that key and
   `adminAuthHeader()` now includes `iatMs`.
3. **Upload refusal race (real bug in `src/app.ts`).** `/api/agent/upload` and `/api/agent/upload-installer` answered 400
   before the asynchronous `fs.unlink` of the temp file finished, so a caller (and the t11-api tests "refuses bad input
   and removes the temp file" / "stores an installer...") could still see the file in `.incoming`. Fix: `removeUpload()`
   deletes synchronously before responding, on all four refuse/500 paths.
4. **supertest server churn: "socket hang up".** `request(app)` starts and closes a new server on an ephemeral port for
   every request. With ~400 requests per file across 10 workers, ports are reused while old connections are still
   closing and the next request dies with ECONNRESET or "socket hang up". Fix: `test/support/supertest.ts`
   (jest `moduleNameMapper`) gives each app ONE server per test file, closed in an afterAll
   (`test/support/afterEnv.ts`). Also `test/env.ts` turns off keep-alive on the global http agent so no pooled
   socket can outlive its server. (Gotcha found on the way: the server must bind synchronously (`listen(0)` without a
   host), otherwise supertest sees no address, listens again itself and closes the shared server after request one.)
5. **Shared filesystem paths.** UPLOADS_DIR, INSTALLERS_DIR, AGENT_BINARIES_DIR and DB_PATH defaulted to the repo's
   `server/uploads`, `server/data`, ... for every suite that did not override them. `test/env.ts` now points all four at a
   per-test-file temp root (removed on exit); `t11-api` / `t6-helpers` still override with their own dirs.
6. **Late logging after teardown** ("Cannot log after tests are done", t2-ws-auth): the server-side ws `close` event
   fires one tick after `server.close()` calls back. The suite's afterEach now yields two `setImmediate`s.

Checked and fine (no change needed): ports are all `listen(0)`; the maintenance timers, ping sweep and relay stale
interval are already unref'd and cleared on server close; wsTicketStore has no timers; rate limiters are reset per test.
