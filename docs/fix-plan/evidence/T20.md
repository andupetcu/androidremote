# T20: hide unsupported commands on Android, root-only remote desktop (web-ui)

Owner decisions: (a) unsupported commands hidden for Android (or unknown OS), not disabled; (b) remote desktop only on rooted Android.

## Changes
- `lib/agentSupport.ts`: removed `ANDROID_UNSUPPORTED_HINT`; added `ROOT_REQUIRED_MESSAGE` ("Remote desktop requires a rooted device") and `isRootRequired(reason)`.
- `DeviceCommands`: Play Sound (the only control for an unsupported type) is not rendered for Android/unknown OS; hint UI and its CSS removed.
  Audit of other trigger sites: DeviceApps (launch/enable/disable/permission/protect), DeviceKiosk, volume, lock/reboot/wipe/screenshot/location/telemetry/policy all use supported types; Devices page, groups and policy editors expose no command types. Unused helpers (unlock, brightness, message) are wired to no control.
- `DeviceTelemetry.rooted?: boolean | null`, mapped in `useTelemetry` (non-boolean = unknown).
- `DeviceRemote` (Android path): `rooted === false` disables Connect and shows the message; unknown/true allows. A failed START_REMOTE whose error mentions root required shows the message.
- `RemoteScreen`: CAPTURE_FAILED reason `root_required` shows the message instead of "Screen capture failed...". No "Start now"/consent_required text existed in the UI (nothing to remove).
