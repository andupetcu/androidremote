## Ack semantics
Unknown command or command of another device: 404. completed/failed: 409. `expired`: 410. Repeated `executing` ack: 200 (idempotent). 410 relies on the command lifecycle owner adding the `expired` status; the test forces it in SQL.

## Decision: enroll serverUrl contract
`POST /api/enroll/device` returns `serverUrl` = http(s) base URL (unchanged server behaviour). Android uses it for REST (`EnrollmentApiClient`, MainActivity, polling service already map ws->http, so both forms work) and the device derives `ws(s)://.../ws` itself (T8a). The skipped test now asserts http(s) base without path and is unskipped. `/pair/status` still returns the ws signaling URL (legacy pairing flow, untouched).

## Deployment notes (env)
- `ADMIN_INITIAL_PASSWORD` (>= 8 chars) or `ADMIN_PASSWORD_HASH` must be set, otherwise login is refused. A stored hash wins; remove the initial password after first start.
- `TRUST_PROXY` (e.g. `1`) behind Nginx Proxy Manager so the login limiter sees the real IP; default stays `loopback`.
- `ALLOW_TOKENLESS_DEVICES=true` only during migration until all devices run the T3 build (they send X-Session-Token); then remove it.
- Pairing: `/pair/complete` now needs the admin JWT.
