## Changes
- `db/schema.ts`: `migrateDeviceCommands` is one `db.transaction` (new table, copy by column name, drop, rename); adds `lease_expires_at`, `expires_at`, status `expired`; no-op when current. Rows of removed command types are dropped with a logged count. Pending/delivered legacy rows get `expires_at = created_at + TTL`. `sha256` columns on `app_packages` and `app_versions`. `commandTtlMs`.
- `services/commandStore.ts`: `queueCommand(..., {supersede})`, `expireStale`, lease-based `getPendingCommands` (transaction), `hasPendingOfType`, device-scoped `acknowledgeCommand` / `cancelCommand`, `expired` status.
- `services/appSyncService.ts`: sha256 in policy INSTALL_APK (superseded per package), `queueSyncPolicy` (superseded per type).
- `services/uploadStorage.ts` (new): multer storage engine, streams to `uploads/.incoming`, sha256 while streaming. `services/apkValidator.ts` (new): package-name regex, zip magic and central-directory check for AndroidManifest.xml, streaming file hash. `services/iceServers.ts` (new).
- `services/storageProvider.ts`: `resolveSafe` containment on every operation, `adopt` (rename, EXDEV copy fallback).
- `services/appPackageStore.ts`: sha256 on packages and versions, lazy backfill from disk, `getSha256ForDownloadUrl`, injectable db (`setDatabase`), `runInTransaction`.
- `app.ts`: heartbeat, poll, ack (expiry sweep, scoped), delete scoped; one `finalizeCommandPayload` used by `/api/commands`, `/devices/:id/commands` and batch (START_REMOTE `signalingUrl` + `iceServers`; INSTALL_APK sha256, 400 when none can be determined); upload route rewritten (validate, inspect, adopt, DB transaction, cleanup, 413/400 JSON errors); authenticated `/api/uploads/apks/*` replaces the public `express.static`; `GET /api/ice-servers`; `getBaseUrl` is env-only; `/pair/status` one-time.

## Env vars
New/changed (all optional): `PUBLIC_BASE_URL` (external URL; `BASE_URL` still read; fallback `http://localhost:$PORT`, no Host header), `UPLOADS_DIR`, `COMMAND_LEASE_MS` (300000), `COMMAND_TTL_SHORT_MS` (900000), `COMMAND_TTL_DEFAULT_MS` (604800000), `STUN_URLS` (default Google STUN), `TURN_URLS`, `TURN_SECRET`, `TURN_TTL_SECONDS` (3600). Deployments MUST set `PUBLIC_BASE_URL`, otherwise enrol responses, installers and START_REMOTE point at localhost. coturn needs `use-auth-secret` with the same `static-auth-secret` as `TURN_SECRET`.

## Behaviour changes other owners should know
- `INSTALL_APK` queued by hand needs `payload.sha256` unless its url is one of our uploads (then the stored hash is used). Existing `commands.test.ts` INSTALL_APK cases got a `sha256` field for this reason (3 lines).
- `GET /api/uploads/...` and `GET /api/ice-servers` need an admin JWT or an enrolled device token (new "any principal" class in `middleware/apiGate.ts`); the public `/uploads/` entry is gone. The web UI must not use `<a href>`/`<img>` on these without a header. `/api/downloads/agent|installer` stay public (not in scope).
- `GET /api/pair/status/:id` returns the token once; a device that loses that response must re-pair.
- Duplicate final ack stays 409 (T1 contract; device treats it as already done). Idempotency is at state level: nothing changes, no second event.

## Not done / limits
- Agent binary and installer uploads (`agentBinaryUpload`, `installerUpload`, 200 MB each) still use `memoryStorage`; `agentBinaryStore.save` takes a Buffer. The APK path (500 MB) is the one that was in scope; convert these two with the same engine when T11 touches `agentBinaryStore`.
- `executing` commands are never redelivered or expired by the server (the device acks failed on restart, T3). A device that dies mid-command leaves it `executing` until an admin looks; a sweep for very old `executing` rows is optional.
- `device-offline` events (SR-15 note) are not emitted.
- The rebuild migration was tested on in-memory databases, not on a copy of a production file.
- WIPE `confirm` and the six C10 command types are T11 (FOLLOWUPS).
