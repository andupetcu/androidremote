## What changed
- `signaling.ts`: authentication during the HTTP upgrade. `/admin` needs `?ticket=` (admin). `/ws` needs `?ticket=` (signaling, controller) or `Authorization: Bearer <device session token>` (device, validated with `validateSessionToken`, expiry included). Result is kept per request and used by `join`. Role comes from the credential. Device token must match the joined deviceId; a ticket bound to a deviceId may only join that room. A taken role is replaceable only by the same principal (`device:<id>` / `controller:<subject>`) or if the old socket is dead; otherwise `Role X already taken in this room`. Late close of a replaced peer notifies nobody (SR-07); no `peer-left` is sent at replacement either (the other side gets `peer-joined`). Second `join` on one socket is rejected. `setupSignaling(server, { db? })` takes an optional db (default `getDatabase()`).
- `relay.ts`: viewers need `?deviceId&session&ticket` (purpose relay, ticket deviceId must equal the URL deviceId); the `token=` JWT / session-token viewer path is removed. Agents still authenticate with AUTH_REQUEST, now via `validateSessionToken` (expiry enforced). Pre-auth buffer capped at 64 KB (close 1009), auth timeout stays armed until auth finishes, duplicate AUTH_REQUESTs ignored. Viewer may only send message types of its own session type (+ telemetry request). `removeAgentIfSocket` for close/error (SR-05). Ping/pong sweep on all three servers, `maxPayload` set (relay 70 KB, admin 64 KB, signaling 1 MiB), `sendWithBackpressure` (drop DESKTOP_FRAME, else close 1013 above 8 MiB buffered), viewer limits.
- `agentConnectionStore.ts`: `removeAgentIfSocket`, `getTotalSessionCount`, replaced agent's viewer sessions are closed, u16 channel ids recycle instead of overflowing.

## Needs from other owners
- T1 (`POST /api/ws-ticket`): a `relay` ticket MUST carry the `deviceId` (relay viewers are rejected without it); `subject` should be the admin username (it is the controller identity for eviction rules). A `signaling` ticket may omit deviceId, but binding is recommended.
- Android (T8a): the device must send `Authorization: Bearer <session token>` on the `/ws` upgrade; the join message's `role` is ignored. Without it the upgrade is 401.
- `index.ts` needs no change (`setupSignaling(server)` still works).
