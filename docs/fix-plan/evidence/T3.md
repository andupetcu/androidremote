## What changed (production)
- `api/DeviceHttpClient.kt` (new): single client factory. Ktor plugin adds `X-Session-Token` per request, only to the server host. Used by CommandApiClient, TelemetryCollector, SilentPackageInstaller (downloads) and the service (inventory, app-updates). HttpTimeout installed.
- `api/CommandApiClient.kt`: requires an injected client; `AckResult` (OK/REJECTED/UNAUTHORIZED/RETRY_LATER); acks retry on 5xx and exceptions (2 s, 4 s), 4xx are permanent; 401 on poll gives `UNAUTHORIZED`, with 404 both `isEnrollmentInvalid`; new `postTelemetry`, `postApps`, `getAppUpdates`.
- `api/CommandModels.kt`: `expired` status; `AppUpdatesResponse`/`AppUpdateEntry` moved here, entry gains optional `sha256`.
- `mdm/CommandStateStore.kt`, `mdm/CommandProcessor.kt` (new): persistent ring of 200 command ids with stored results, pending-ack queue, ack executing before and completed/failed after, `withTimeout` (10 min install, 2 min other), in-flight set against redelivery, installs/uninstalls serialised behind a lock but off the poll loop.
- `mdm/PollBackoff.kt` (new): backoff with jitter, capped at 5 min; `runPollLoop` stops on 401/404.
- `mdm/CommandPollingService.kt`: uses the above; `EnrollmentState` flag plus notification when enrollment is invalid; app-update check runs in the install scope; inventory built by `AppInventory`; `isRunning` flag; battery exemption and watchdog scheduled.
- `mdm/PollingWatchdog.kt` (new): WorkManager periodic 15 min worker restarting a dead service. `app/build.gradle.kts` adds `androidx.work:work-runtime-ktx:2.9.1`.
- `mdm/BatteryExemption.kt` (new): as Device Owner grants itself REQUEST_IGNORE_BATTERY_OPTIMIZATIONS then opens the system request.
- `mdm/ApkFetch.kt` (new): `InstallUrlPolicy`, `ApkVerifier`, resumable `ApkDownloader` (Range, length check, storage check, socket timeout), `VerifiedApkFetcher` (policy, sha256 required unless `BuildConfig.ALLOW_UNVERIFIED_APK`, hash compare, delete on mismatch), `InstallStatusMapper`.
- `mdm/SilentPackageInstaller.kt`: `installFromUrl(url, pkg, sha256, serverBaseUrl)`; no more user-prompt fallback (non-Device-Owner returns an explicit failure, AM-21); session abandoned on every failure path and callback unregistered (AM-13); `UserPromptShown` removed.
- `mdm/InstallResultReceiver.kt`: STATUS_PENDING_USER_ACTION now reaches the callback, which reports a failed result instead of hanging (AM-03).
- `mdm/TelemetryCollector.kt`: Ktor client with the token (OkHttp ad-hoc client removed); `sendTelemetrySuspend`, with the blocking `sendTelemetry` kept for MainActivity.
- `app/build.gradle.kts`: `ALLOW_UNVERIFIED_APK=false`.

## Could NOT test or fix (and why)
- AM-11 battery exemption: Android has no silent whitelist API, so the system dialog may still need a tap. The real call path (DevicePolicyManager grant plus ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS) needs a device; only the decision (`BatteryExemption.plan`) is unit-tested. `DeviceOwnerManager.exemptFromBatteryOptimization()` is still a stub but is outside T3's files; the new `BatteryExemption` object replaces its use in the service.
- WorkManager worker (`PollingWatchdogWorker`) is not run in a test (needs work-testing and a real service start). Only `shouldRestart` is tested.
- PackageInstaller session code (`installSilently`, abandon on failure) needs a real device; the logic around it (status mapping, hash, URL, download) is extracted and tested.
- Foreground-service start from a Worker on Android 12+ is allowed for Device Owner apps; not verified on a device.
- REBOOT and WIPE: if the process dies before the final ack, redelivery after the lease acks `completed` for these two types (intentional, documented in CommandProcessor). The WIPE `confirm` check (C10) is not in T3.
