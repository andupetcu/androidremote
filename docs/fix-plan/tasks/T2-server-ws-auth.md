# T2: WebSocket authentication: signaling, admin events, relay (Phase 0, plus WS robustness)
Model: Sonnet. Findings: SS-02, WU-02 (server side), AR-01 (server side), SS-05, SS-03, SR-05, SR-06, SR-07, SS-15 (relay pre-auth buffer).
Owned: server/src/signaling.ts, server/src/relay.ts, server/src/services/agentConnectionStore.ts, and new tests server/test/t2-*.test.ts. Existing server/test/signaling.test.ts may be updated for the new auth.
Read only: wsTicketStore.ts (`consume`), server/src/db/schema.ts (sessions table), the existing `validateSessionToken` (import it; don't edit its file).

Do (contracts C3, C4):
1. Authenticate during the HTTP upgrade, before `handleUpgrade`. For `/admin`, require `?ticket=` with purpose admin; otherwise write `HTTP/1.1 401 Unauthorized\r\n\r\n` and destroy the socket. For `/ws`, accept either `?ticket=` (purpose signaling, which makes the peer a controller) or `Authorization: Bearer <device session token>` (which makes it a device). Keep the result on the socket.
2. In `join`, take the role from the credential and ignore the message's `role`. A device token must match `deviceId`. A controller ticket bound to a deviceId may only join that room. Replacing a peer is allowed only for the same authenticated principal (same device token or same subject); otherwise reject the new join. Fix the spurious `peer-left` after a replacement (SR-07).
3. Relay: browser viewers authenticate with a ticket of purpose relay bound to the deviceId. Desktop agents keep device-token auth, but the token must be bound to that agent's device and must not be expired. Cap the pre-auth buffer (for example 64 KB) and keep the auth timeout until auth completes. Fix the reconnect race where a late `close` from the old socket removes the new connection (compare socket identity). This is SR-05.
4. Ping/pong heartbeat every 30 s on all three servers; terminate peers that miss two pings. Backpressure: if `ws.bufferedAmount` is over a limit (for example 8 MB), drop frames for video-like relay traffic or close. Cap concurrent sessions per device and globally through env, with sensible defaults.
Tests first: anonymous /ws and /admin upgrades are rejected; a device token for A cannot join room B; a controller ticket for A cannot join B; an unauthenticated peer can't evict; same-principal replacement works and sends no spurious peer-left; the relay viewer needs a ticket bound to the device; an expired relay token is rejected; the late-close race no longer removes the new connection.
